# PQL-016: broker interface

Hypothesis: one abstract execution contract lets engine callers depend on a broker
boundary without depending on a vendor SDK or a particular simulator.

Problem: no common broker interface exists. Learning objective: C++ permits an
incomplete return type in a function declaration, allowing the interface to precede
the implementation without inventing placeholder financial models.

Generation target: `src/execution/broker.hpp`, declaring exactly
`Execution execute(const Order&, const MarketState&)` as pure virtual, with a
defaulted virtual destructor. Inputs are borrowed const references; the eventual
result is returned by value. The interface is available through existing domain
include paths and adds no dependency or separate compiled library.

Resolution signal: a self-contained header compiles, exact signature/abstractness/
virtual destruction assertions pass, and a declared override satisfies the abstract
contract. The test deliberately does not instantiate a concrete broker.

Constraints: interface only. No order execution, networking, persistence, portfolio
mutation, fee calculation or live brokerage integration is introduced.

Required before concrete use: define `Execution`; define `MarketState` before
inspecting its contents. C++ allows both forward declarations here. Defining or
calling `execute` requires the complete value-returned `Execution`, while a
reference to `MarketState` can be passed without its definition.
`Execution` is not an alias of `Trade`: a successful full-fill trade
does not define rejected outcomes or costs. Their fields and outcome semantics
belong to the concrete execution work, not this declaration ticket.

Unknowns deferred explicitly: fill/rejection semantics, fees, cash/holdings context,
duplicate-order handling and decision-time market availability. Const references
alone do not enforce authorization or prevent look-ahead. Preserve the flow from
order through execution to transaction and portfolio; strategies must not mutate
portfolio balances directly.

Validation: MSVC C++20 Debug build (`cmake --build build`) and all nine default
CTest suites (`ctest --test-dir build --output-on-failure`) passed, including
BrokerContractTest. The new C++ files pass clang-format 22.1.8 with the repository
style. Architecture, quant and C++ static reviews found no blocking issues;
minor include-order and completeness wording findings were corrected before the
final build. Linux/CI and optional PostgreSQL/provider suites were not rerun for
this declaration-only change. Concrete broker execution remains unimplemented.
