# PQL-021: weekly dollar-cost averaging baseline

Hypothesis: a fixed weekly SPY purchase rule provides a reproducible behavioral
baseline for comparison with immediate SPY buy-and-hold. Problem: no recurring
strategy exists. Learning objective: periodic allocation, transaction costs and
accepted-history scheduling without changing execution/accounting responsibilities.
Generation target: DollarCostAveraging Strategy and offline fixtures.
Resolution signal: $25-budget Monday buys recur, same-day repeats do not fill,
and a prefunded run remains reconstructable from transactions.

## Rule and use

Include `strategy/dollar_cost_averaging.hpp` and link `pql_simulation`.

```cpp
pql::DollarCostAveraging strategy{costs};
// pair is a PaperPortfolioPair; market is the current decision-time SPY quote.
const auto proposals = strategy.generateOrders(market, pair.paperState());
for (const auto& order : proposals) {
    const auto execution = pair.executePaper(order, market);
    // Inspect execution.isFilled() / rejectionReason() and obtain a fresh snapshot.
}
```

Execute immediately using the same MarketState quote and TradingCosts used for
sizing. The strategy only observes and proposes; broker validation and ledger
mutation remain separate. The $25 budget sizes a market order, not a hard spending
cap: 0.25 shares proposed at $100 would cost $30 if instead filled at $120. Changed
conditions require regeneration from a fresh observation, not execution of a stale
proposal. Delayed execution with a guaranteed cash cap would require another order
contract and is outside this simple simulator.

- Buy SPY on the supplied timestamp's UTC Monday, using fractional shares.
- Spend at most $25 total, including commission. Size against the slipped buy price
  using the same checked cash-budget helper as the buy-and-hold strategy.
- Require at least $25 cash; never spend a smaller final remainder. Commission
  consuming the budget or unrepresentable sizing produces no proposal.
- Use existing cash. No recurring external contribution is added.
- Skip non-SPY quotes and non-Mondays. No Monday quote means no purchase, with no
  Tuesday catch-up. No exchange calendar, holiday substitution or wall-clock task.
- Any accepted SPY Buy on that UTC date suppresses another purchase. History has
  no strategy attribution, so this includes manual/other-strategy buys that day.

This schedule is intentionally simple. UTC day is an explicit simulation convention,
not an exchange-local session inference. Portfolio history later than the eligible
decision timestamp throws std::invalid_argument, rather than using future holdings.
Callers still must supply correctly aligned market and portfolio observations.

## IDs, retries and execution

For the current sequential per-portfolio simulation, the proposed ID is one greater
than the maximum accepted order ID (1 for empty history). Gaps are respected and
INT64_MAX exhaustion yields no proposal. Repeated calls with the same state generate
the same order ID; broker uniqueness prevents double fills from stale copies.

There is no internal 'already invested' flag. Recreated strategies see accepted
ledger history. A rejection leaves the opportunity and next ID unchanged. Always
execute synchronously and refresh state after accepted fills. Concurrent strategies,
pending ID reservations, delayed fills across dates and global ID allocation are
outside this contract; they need orchestration beyond this ticket.

## Numeric example

With $1,000 cash and $1 commission, a Monday SPY price of $12 buys two shares:
$24 notional plus $1 commission leaves $975 cash and $12.50 average cost. At $24
the following Monday, it buys one share and leaves $950 cash, three shares and $50
total cost basis. At that mark the portfolio is worth $1,022. Costs and trade
history are sufficient to replay the state.

With zero costs and a constant $100 price, 40 Monday purchases of 0.25 shares use
the original $1,000; the 41st Monday produces no order. The SPY control bought at
inception stays independent. Changing prices give the two allocation schedules
different outcomes; this is a baseline, not evidence that DCA outperforms.

Seven tests cover scheduling, existing holdings, costs, rejection/retry, restart,
ID gaps/exhaustion, UTC/pre-epoch boundaries, replay and the 40-week pair simulation.
Shared sizing retains the benchmark's downward rounding regression. Runtime and
review evidence are in `.codex/reviews/PQL-021/`.
