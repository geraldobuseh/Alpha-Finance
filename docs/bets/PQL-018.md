# PQL-018: configurable market friction

Hypothesis: deterministic commission and adverse slippage expose the cost of
trading without changing the strategy-facing Broker interface or ledger rules.
Problem: FakeBroker supports a flat fee but always fills at the reference quote.
Learning objective: distinguish commissions, execution-price friction and turnover.
Generation target: validated TradingCosts, adjusted execution prices, regression
tests and notes/006-market-friction.md.

Resolution signal: quote $100 with 5 bps fills buys at $100.05 and sells at $99.95;
cash, basis and realized P&L include both costs exactly once; replay matches state.
Constraints: full fills, single currency, deterministic fixed bps, existing atomic
ledger mutation. No spread/order-book model, extra infrastructure or live trading.

## Configuration

```cpp
// portfolio is a trusted Portfolio owned by execution orchestration.
const pql::TradingCosts costs{pql::Money::create(1.0).value(), 5.0};
pql::FakeBroker broker{portfolio, costs};
```

Commission is a fixed single-currency amount per successful full fill. Slippage is
in basis points, where 1 bp = 0.01%. Configuration rejects negative commission,
nonfinite slippage and slippage outside [0, 10000) with std::invalid_argument. The
upper bound keeps the mathematical sell price positive. Money already excludes
nonfinite commission. Explicit zeros are valid; there is no hidden default cost.

The prior `FakeBroker(portfolio, Money fee)` constructor remains compatible and
means that commission with zero slippage. TradingCosts owns its validated values
and exposes read-only commission()/slippageBasisPoints() getters.

MarketState::price() is the unmodified reference quote. Orders are market orders
and contain no requested price. Buy execution adds quote*(bps/10000); sell
execution subtracts it. Cash checks and Trade construction use this adjusted price.
Transaction::fees() contains commission only. The receipt and ledger expose actual
fill price and commission; slippage is not subtracted separately.

Zero slippage uses the exact original quote. Positive slippage that underflows,
vanishes through rounding, overflows or creates a nonpositive price returns
InvalidArithmetic with no mutation or fee. The existing ledger retains final
numeric-loss checks. Result-copy exception safety remains unchanged.

Replay uses recorded fills and fees, so changing current configuration cannot
rewrite past accounting. Persisting experiment configuration and reference quotes
for slippage attribution remains future experiment/audit work; this ticket changes
no database schema. Fixed slippage is an assumption, not a liquidity guarantee.

## Validation

Six additional FakeBroker tests cover the numeric example, both directions,
independently configurable costs, zero-cost/legacy compatibility, deterministic
replay, fee-inclusive affordability, sell-fee shortfalls and arithmetic extremes.
Runtime evidence and reviewer findings are in `.codex/reviews/PQL-018/`.
